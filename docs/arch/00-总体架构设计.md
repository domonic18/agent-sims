# agent-sims 总体架构设计

> 定稿日期: 2026-10-03 · 技术方案 v1(与 requirement v1.4 配套)
> 本文是终态方案入口;细化设计按主题另开编号文档(01、02…),并在 docs/README.md 登记索引。

## 1. 技术选型总览

| 层 | 选型 | 说明 |
|---|------|------|
| 客户端渲染 | Phaser 3 | 2D 像素世界;update() 读 store 插值渲染 |
| 客户端 UI | React + Vite + Zustand | HUD/面板;Zustand 为唯一状态源 |
| 后台管理 | React Admin | 挂 /admin 路由级懒加载,同一构建产物 |
| 服务端 | Node.js + TypeScript + Fastify | 单进程单体 |
| 实时同步 | Socket.IO | JSON 快照+增量;玩家/参观者同一条流 |
| 数据库 | PostgreSQL 16 + pgvector | ORM: Drizzle;迁移: drizzle-kit |
| 模型接入 | ModelRouter(OpenAI 兼容适配) | 慢思考LLM / 轻量对话LLM / Jev(System One) / embedding,均在后台配置 |
| 推送 | 飞书自定义机器人 webhook | 加签 + 串行队列(限流 100/min 足够) |
| 仓库 | pnpm workspace | apps/web、apps/server、packages/shared |
| 交付 | Docker Compose | app + postgres 两容器 |

**选型理由摘要**: 单机自部署、1 玩家+数参观者规模,KISS 优先。Colyseus 为多房间生命周期设计,单一持久世界用不上;pgvector 对几万条记忆暴力扫描毫秒级够用;全部模型走适配层——模型选型是后台运维配置,不是架构决策。调研依据见 research/02。

## 4. 世界模拟设计

- **时钟**: 1 现实秒 = 1 游戏分钟(1 游戏日 = 24 现实分钟);服务端固定 1000ms tick,accumulator 模式(Fix Your Timestep)
- **昼夜节律**: 世界有昼夜循环;夜间角色进入睡眠活动(见 §6.4)
- **tick 职责边界**: tick 只推进连续量(位移/体力幸福衰减/睡眠恢复);到达目的地、动作完成、对话开始等**离散事件即时触发决策**,不占 tick
- **暂停**: 停止推进模拟时钟,连接层照常;暂停优先于一切模拟含离线模拟(requirement §2.5)
- **权威状态**: 世界状态唯一权威在服务端;客户端只做渲染+输入

## 5. 意图指令层(托管/接管的根基)

- 指令集(Zod schema,packages/shared 为唯一协议源): `move_to / do_activity / say / buy / sleep / ...`
- **双来源**: 玩家输入与 Agent 规划器是同一指令层的两个来源;**托管⇄接管 = 指令来源原子切换**(纯状态翻转,<1s,世界状态不丢)
- 指令执行产生事件 → 写入记忆流 → 影响后续决策
- **决策气泡** = 当前意图 + 决策理由(来自规划文本/方针缓存/模板拼装)

## 6. Agent 内核(逐模块对照 Generative Agents 开源实现)

### 6.1 感知与记忆写入
- 服务端把角色附近的事件推入其记忆流
- 写入时由 **Jev 打重要性分(1-10)**——原版用 GPT-3.5 打分,Jev 毫秒级+免费层足够

### 6.2 记忆流(Memory Stream)
- 存储: `memories` 表(character_id, content, type, importance, embedding(pgvector), game_time, 状态标志)
- 条目类型: `event`(事件) / `insight`(反思洞察) / `dream`(梦境) / `dialogue`(对话摘要)
- 检索: 三因子 min-max 归一化等权——recency=0.995^距上次检索游戏小时 / importance / relevance=pgvector 余弦
- **记忆可查看**: 记忆面板按类型查看(玩家 Agent 游戏内;NPC 记忆点击角色只读查看)

### 6.3 反思(日间补充)
- 未反思记忆 importance 累计 ≥ 阈值(150 起步,后台可调)触发;慢思考 LLM 从 top-100 记忆生成洞察,回写为 `insight`

### 6.4 睡眠与记忆固化(梦境整理,requirement v1.4)
角色像人一样需要睡觉休息;**睡觉是记忆固化的主窗口**:

- **睡眠活动**: 夜间按作息入睡;睡眠中体力恢复;缺觉/熬夜触发软惩罚(次日效率/幸福下降)
- **梦境整理(每游戏日睡觉时)**: 入睡后对当天记忆批量固化——
  1. 打分复核与去重压缩(Jev/规则)
  2. 生成「梦境」: 以当天记忆为素材,慢思考 LLM 产出 1~3 条洞察/情绪总结,回写为 `dream` 条目,当天 event 标记已固化
  3. 核心 NPC 用轻量 LLM 做简化版;背景NPC 仅规则摘要,零 LLM
- **成本**: 每角色每游戏日 1 次批量进行,确定性调度窗口,天然低频;日间只保留阈值反思作重要事件补充
- **离线衔接**: 离线期间的睡眠整理照常进行(与 requirement §4 离线降频一致)
- **研究背书**: Sleep-time Compute(Letta+UC Berkeley 2025)——空闲/休眠期预计算整理上下文,同等准确率测试期计算量降约 5 倍;「Do Language Models Need Sleep?」(2026)亦验证类睡眠固化机制

### 6.5 规划(Planning)
- 日计划每游戏日 1 次(含入睡时间)→ 小时块 → 15 分钟块,写回记忆流
- 执行中快层判定 continue/react;观察与计划矛盾(场所关门等)才局部重规划
- 离线降频与原版行为天然一致(日计划本就是 1 次/日)

### 6.6 决策路由(成本分级,requirement 根本原则 2)

| 任务 | 引擎 | 频率 |
|------|------|------|
| 寻路/活动执行/数值增减/背景NPC日常 | 规则引擎 | 每 tick |
| 微决策(候选中选一个)/记忆打分/事件分类/continue-react 判定 | Jev(System One) | 高频 |
| 核心 NPC 对话生成/梦境简化 | 轻量小 LLM | 中频 |
| 日程规划/反思/梦境洞察/玩家Agent关键社交 | 慢思考 LLM | 低频 |

- Jev(System One)只能输出类型化答案(choice/score),**不做对话生成**(调研实测,codiv.ai)
- 慢→快交接(Talker-Reasoner 模式): 慢思考异步写「方针/洞察缓存」,快层读缓存决策不阻塞
- **记账**: 每次调用写 `token_usage`(角色/任务类型/tokens/成本),后台成本面板展示,超阈值飞书告警

### 6.7 决策可见
- 行动气泡: 意图+理由;记忆面板: 全类型条目(event/insight/dream/dialogue)可查看

## 7. 同步与参观

- Socket.IO: 连接时声明角色 player/spectator;首连全量快照,后续增量(带 tick 序号);断线重连靠快照重同步
- 服务端**丢弃 spectator 的指令**(参观只读,requirement §2.1)
- 客户端: WS 层写 Zustand;Phaser update() 读 store 按路径段插值;React UI selector 订阅;EventBus 仅瞬态信号(镜头聚焦等)

## 8. 数据模型(主要表)

| 表 | 说明 |
|----|------|
| characters | 角色: tier(player/core/background)、人设卡 JSON、作息、位置、数值 |
| memories | 记忆流: type(event/insight/dream/dialogue)、importance、embedding、固化/反思标志 |
| schedules | 日/小时/15分钟计划 |
| dialogues | 对话记录 |
| world_state | 游戏时钟/暂停/昼夜/世界版本 |
| model_configs | 模型槽位(慢思考/轻量/Jev/embedding): base_url、model、AES 加密 key |
| token_usage | 调用记账(角色/任务类型/tokens/成本) |
| admin_users | 后台账号 |
| events | 世界事件流水(参观回放/调试基础,后置) |

- schema 定义于 `apps/server/src/db/schema/*.ts` 按域拆分(world/memory/agent/sys)
- **迁移纪律**: forward-only,drizzle-kit 生成入 git,禁止手改已应用迁移;0000 迁移含 `CREATE EXTENSION vector`
- 启动顺序: **migrate → seed(幂等基础数据) → 世界循环**;备份 pg_dump

## 9. 后台管理(React Admin @ /admin)

- 模型配置: 角色槽位 CRUD,Key AES 加密存储,页面不明文回显
- NPC 管理: 人设卡/tier/作息 CRUD,新增入场、删除退出
- 成本面板: token_usage 统计图表 + 告警阈值
- 世界控制: 暂停/恢复、时间流速
- 飞书 webhook 配置
- 鉴权: 单管理员,初始密码 env 提供,登录后 session

## 10. 部署架构

- **生产**: `docker compose -f docker/docker-compose.yml up`——app(多阶段构建,静态托管 web 产物) + postgres(pgvector 官方镜像),数据落 `workspace/postgres`(bind mount,宿主机可直接备份/重置),配置 .env
- **开发**: `docker/docker-compose.dev.yml` 只起 postgres;前后端本地 `pnpm dev`(Vite proxy → server)
- env 清单: `DATABASE_URL / MASTER_KEY(AES根) / ADMIN_INITIAL_PASSWORD / GAME_PORT / NODE_ENV`;模型与 Key 一律走后台管理,不进 env(requirement §2.6)
- CI/镜像推送: 后置
