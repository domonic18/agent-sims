# 生产系统设计(采集·制作·修补——生存引擎地基)

> 创建日期: 2026-10-05 · 用户定稿: 游戏引擎须为 M-S 生存线(采集→制作→建造→修补→塔防)打好地基——三环先在成长模式以玩法先例落地,生存模式换皮复用
> 关联: 07-survival-design.md(复用方)、08-maintenance-design.md(修补先例与 work_task 模型)、04-numerical-design.md §5.4(数值权威)、06-worldgen-design.md §3(节点撒点/站点槽位)

## 1. 设计立场: 引擎先行,玩法验证

- 生存五环(采集/制作/建造/修补/塔防)中,采集/制作/修补不需要等生存模式才铺引擎——在成长模式各落一个**最小先例**,人工与 Agent 先跑通,生存模式换内容复用管线
- 三环共同抽象 = **三类世界目标实体 + 统一作业模型**:

| 引擎概念 | 实体形态 | 成长先例 | 生存复用(S1/S2) |
|---|---|---|---|
| **资源节点**(采集) | 有存量,采完枯竭重生 | 浆果丛/拾荒堆 | 树→木材/岩石→石料/废墟→金属 |
| **制作站点**(制作) | 锚点家具+配方表 | 灶台@餐厅/木工台@办公楼 | 合成台(武器/工事/物资) |
| **可损耗实体**(修补) | 有破损态,修好恢复 | 围栏(08 已定) | 墙体/尖刺/瞭望塔(波次后) |

- 损耗来源演进: 成长=环境磨损(定时 roll,08)→生存=僵尸攻击(事件驱动)——损耗生成器接口一致,只有触发源不同

## 2. 采集(物品型作业)

- **节点实体**: `{ id, kind: 'berry_bush'|'junk_pile', x, y, charges, respawnAtDay }`——与 08 maintenance spot 同一实体体系(统一快照协议)
- **采集作业**: `work_task`(目标=节点)→ 到位作业计时 → 产出入背包(背包满拒单) → charges-1 → 0 时枯竭进重生计时
- **无工资,物品即收益**——免费食物/材料路线,与工资型作业(维护岗)构成双轨奖励模型
- 拾荒堆与街道杂物的区分: 杂物是**卫生任务**(清洁工清理后消失),拾荒堆是**资源点**(固定点位可反复采集)

## 3. 制作(配方驱动)

- **配方注册表**: `{ recipeId, inputs: [{itemId, count}], output, stationKind, minutes }`——后台可管理(07 §5 复用承诺),M4 Agent 可读可规划
- **新意图** `craft { characterId, recipeId }`: 校验站点在位 + 材料足(背包扣料) → 作业计时(走活动净速率框架) → 产物入背包
- v1 两条配方串起三环:

| 配方 | 输入 | 产出 | 站点 | 时长 | 意义 |
|---|---|---|---|---|---|
| 浆果派 | 浆果×3 | 浆果派(能量+8 幸福+4) | 灶台@餐厅 | 25 分 | 时间+材料换高价值食物,第一条生产链 |
| 修补钉 | 废料×2 | 修补钉×1 | 木工台@办公楼 | 15 分 | 修理工修补围栏须耗 1 枚——**采集→制作→修补闭环** |

- 修补材料接入: M-G.5 修补免材料;M-G.6 起修理工背包须有修补钉(没有则拒单)——三环由消耗关系焊死
- 站点家具均为**保证场所**现成挂点: 餐厅/办公楼补灶台与木工台槽位(内置图+生成蓝图模板),不新增场所

## 4. 修补(可损耗实体注册表引擎化)

- 08 围栏为首个实例;本文抽通用注册表: `{ kind, 破损素材档, 修补时长, 材料需求, 修补工资 }`——加行即接入新可修物
- 生存复用: 墙体/工事加行 + 波次结算批量损耗(事件驱动触发同一注册表)

## 5. 意图与快照增量(引擎层)

| 项 | 内容 |
|---|---|
| work_task 推广 | target 语义从"损耗点"扩为"节点/损耗点";校验存量/破损态;奖励按实体类型分流(物品型/工资型) |
| craft 意图 | 站点锚点+payload(recipeId);材料校验;复用活动计时框架 |
| 快照 | 节点存量/损耗点照常下发;配方表为静态内容(shared 定义),M4 规划可读 |
