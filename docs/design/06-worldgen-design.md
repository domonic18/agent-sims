# 随机世界生成设计(种子驱动整图 PCG)

> 创建日期: 2026-10-05 · 对应需求基准 v1.5 §2.9
> 消费方: 新世界引导式创建流程;依赖: 素材库 manifest(05-asset-library-design.md §4)。

## 1. 目标与非目标

**目标**
1. 同一随机种子 → 完全一致的世界(跨进程/跨重启可复现)
2. 整图随机:城镇骨架(道路/功能分区/场所数量与选址)+ 建筑(外观)+ 建筑内部(地板/墙/家具选配)全部由生成器产出
3. 生成结果落到现有 TOWN_MAP 数据结构(TileMapDefinition/PlaceDefinition/FurnitureDefinition),**世界模拟层零改动**——寻路/活动/锚点逻辑照常工作
4. 固定地图(现行手工地图)保留为"内置种子"特例,兼容已有存档

**非目标**
- 3D/开放大世界(需求 §7)
- 生成过程中的玩家干预(种子定即全图定;干预式生成后置池)
- 生存模式专属布局规则(安全区/资源点/刷怪点——随生存玩法落地,见 07-survival-design.md §6)

## 2. 生成管线(纯函数,server 侧)

```
seed(字符串) ──hash──▶ PRNG 状态(mulberry32,顺序消费保证可复现)
    │
    ├─① 骨架生成: 地图尺寸 → 功能分区(住宅/公共/绿地) → 道路网
    ├─② 场所生成: 分区内按配额选场所类型/数量 → 选址(满足间距/临路) → 建筑占地/门/入口
    ├─③ 室内生成: 按场所类型选地板/墙体(theme 域约束) → 家具布局模板+素材库随机选配
    ├─④ 户外装饰: 树/灯/花/长椅沿路与绿地撒点
    └─⑤ 校验与修复: 连通性(所有门可达主路)/活动锚点齐备(每场所 rest/study/work 锚点存在)/家具不重叠
         │
         ▼
TileMapDefinition(与现行 TOWN_MAP 同构) + 生成报告(seed/参数/场所清单)
```

- **可复现性纪律**: 生成器为纯函数,仅依赖 (seed, gameType, params, manifestVersion);禁止生成过程中读时钟/全局随机;manifest 版本入种子派生——素材库变更导致的差异显式可见
- **参数(worldgenParams)**: 地图尺寸档(小 56x48/中/大)、场所密度、绿化率、装饰密度;引导向导第①步配置

## 3. 各阶段规则(首批)

### ① 骨架
- 地图 = 功能分区的矩形拼接(住宅区/公共区/公园绿地),分区内再切地块;主干道"田"字,支路按密度参数加密
- 全图外圈留 1 格边界(柏树墙沿用)

### ② 场所
- 场所配额表(gameType=growth): 公寓×3~4 / 图书馆×1 / 办公楼×1 / 商店×1 / 餐厅×1 / 健身房×1 / 公园×1~2,数量在配额区间内由 PRNG 决定
- **扩展场所池(后置)**: 学校/诊所/旅馆等按池概率出现(配额 0~1 由 PRNG 决定),承载高阶与替代岗位(教师/医生/保洁,见 02-goal-design.md §4.2 岗位表)——高阶岗位市场随 seed 涌现;v1 职业阶梯前四岗全部落在保证场所,不依赖扩展池
- 选址约束: 同类型间距 ≥N 格、至少一边临路(门开向道路)、不越分区
- 建筑占地从尺寸档模板表随机选(如公寓 9x8~12x8)

### ③ 室内
- 地板/墙: theme 约束(公寓→卧室/客厅系,餐厅→厨房系)+tags 过滤,PRNG 从 manifest active 素材抽取
- 家具: 每场所有**布局模板**(床贴北墙/桌居中/柜靠边…),模板含必选 kind 配额(rest/study/work 锚点齐备是硬约束)+可选装饰(plant/tv 按密度);具体素材(哪张床)由 PRNG 从 kind+tier=1 抽取
- **工作锚点槽位(职业阶梯,02-goal §4.2)**: 布局模板按场所类型保证工作锚点——办公楼工位/餐厅与商店柜台(柜台为现有 kind,绑岗时补 use 格)/图书馆书桌;扩展场所带新家具 kind(诊台/讲台),随扩展池落地
- use 格生成: 家具落地后按朝向推导相邻可达格

### ④ 户外
- 行道树沿路间隔撒点(间隔/种类由 PRNG)、灯按路长配额、公园内树/花/长椅密度撒点(沿用现行 decor 坐标生成逻辑并随机化)

### ⑤ 校验
- **连通性**: 全部门格 BFS 可达主干道,失败重roll该场所选址(上限 N 次后降级为换布局模板)
- **锚点齐备**: 每场所活动锚点存在且 use 格可达;不齐备补默认家具
- 校验失败最终兜底: 回退内置固定地图 + 生成报告标注(世界可用性优先)

## 4. 游戏类型分支

| gameType | 骨架 | 场所配额 | 备注 |
|----------|------|----------|------|
| growth(成长) | 上述规则 | 现行类型 | 默认 |
| survival(生存) | 占位:同 growth | 占位:同 growth | 玩法落地后启用专属规则(07-survival-design.md §6),创建向导中标注"敬请期待" |

## 5. 引导式新世界创建(admin 侧)

antd Steps 五步向导重构现行 WorldPanel 创建表单:
①游戏类型(growth/survival)+世界参数(timeScale 上限等) ②agent 人数(1~12) ③人物配置(名称/性别/人设,Form.List 动态行+随机名,现功能平移) ④随机种子(自动生成可手填,附"同种子=同世界"提示+最近用过的种子快捷) ⑤预览确认(展示生成报告摘要:场所清单/地图尺寸/seed)→ 创建
- 创建 API 扩展: body 增 gameType/seed/worldgenParams;server 生成器产出 TOWN_MAP 落库(world 表存 seed 与生成报告)
- **生成预览**: 第⑤步调用 dry-run 生成(不落库)渲染场所清单;地图渲染级预览(缩略图)后置

## 6. 关键决策

| 决策 | 理由 |
|------|------|
| 生成器纯函数 + manifestVersion 入派生 | 可复现是 §2.9 硬需求;素材变更影响显式化 |
| 生成结果落到现行 TileMapDefinition | 世界模拟层(寻路/活动/家具锚点/快照)零改动,风险隔离 |
| 固定地图 = 内置种子 | 兼容已有存档与测试基线(walkability.test 等) |
| 布局模板 + 随机选配,而非自由摆放 | 家具语义锚点(rest/study/work)是玩法硬约束,自由摆放易破坏活动闭环;模板保证可玩性上限 |
| 校验失败兜底回固定地图 | 世界可用性优先于多样性 |
| PRNG 用 mulberry32(32bit,顺序消费) | 种子可枚举/可存储;禁用并发分叉消费(破坏可复现) |

## 7. 分阶段落地(对应 development-plan M-L.4~M-L.5)

1. **M-L.4 生成器**: PRNG/骨架/场所/室内/装饰/校验管线 + headless 单测(同种子一致性/连通性/锚点齐备)+ 内置固定地图种子化回归
2. **M-L.5 创建向导**: Steps 五步表单 + API 扩展 + 生成报告;浏览器端到端(同种子双世界对比截图验收)

## 8. 风险

- **室内布局模板的编辑成本**: 首批 9 类场所各 1~2 个模板手工编写;模板 DSL 保持简单(kind+槽位+朝向),复杂度后移
- **生成质量不可视验收**: 生成报告 + 前端整图缩略渲染(dry-run)作为验收抓手;缩略图渲染列入 M-L.5
- **seed 空间碰撞**: seed 为自由字符串,hash 后 32bit——同图概率极低且无危害(仅多样性损失),接受
