# 目标与激励设计(goal-design)

> 状态: v1.1(2026-10-05)——产品三决策与两个待收敛点均已定稿;繁荣分 v1 公式定稿,特质层留 M4+。
> 维护约定: 改激励结构先改本文档,再动代码(同 numerical-design.md 先例)。

## 0. 与 numerical-design.md 的分工

- numerical-design.md 管「数值如何平衡」: 速率/容量/价格/预算。
- 本文档管「数值为何存在」: 激励、目标、效用。两者冲突时,以本文档修订 numerical-design 相应条目。

## 1. 设计定调(2026-10-05 用户三决策)

| 决策点 | 定稿 | 含义 |
|---|---|---|
| 面向对象 | **Agent 玩,人观察** | 奖励机制=效用函数设计,而非玩家手感设计 |
| 失败惩罚 | **复活扣分**(轻) | 死亡可逆,代价走计分而非世界重开 |
| 世界形态 | **开放世界,涌现叙事** | 无脚本任务线;目标靠行为压力+个性欲望生成 |

推论: 开放世界不需要「关卡目标」,需要**需求压力(让 agent 有事做)+ 个性欲望(让 agent 活得不同)+ 叙事站位(让观察者有剧可看)**。

## 2. 三层目标结构

| 层 | 状态 | 职责 |
|---|---|---|
| ① 需求压力层 | **已有** | 体力/金币/房租构成行为时钟: 不睡会死、不打工没钱、不交租没床。保持现状,不加东西 |
| ② 个性欲望层 | **缺失,M4+ 随 LLM 接入** | 特质权重→效用函数差异化→同一世界不同活法→涌现故事。这是开放世界真正的「目标引擎」 |
| ③ 站位层 | **待建** | 繁荣分生涯账本: 观察者的叙事弧线 + agent 的长期反馈信号。不是胜利条件 |

## 3. 激励现状盘点(2026-10-05)

| 资源 | 机制地位 | 缺口 |
|---|---|---|
| 体力 | 有牙齿(归零=死) | 唯一有真实后果的 |
| 金币 | 半个(房租/食物花销) | 攒多无意义——没有资本形态 |
| 幸福 | **无用途,纯装饰** | 涨跌对世界零影响 |
| 学习 | **纯亏**(耗时耗力无回报) | 理性角色永远不该学习——激励结构有洞 |

结论: 现状只有「避害」没有「趋利」,奖励缺口不是缺反馈,是激励有结构性空洞。

## 4. 奖励机制清单(三层)

### 4.1 即时层(反馈手感,低成本)
- 活动收益飘字(+0.5 币 / 幸福+2 可视化)
- 每日结算卡: 「第 3 天: 赚 32 币 · 幸福 +12 · 存活 ✓」

### 4.2 成长层(让每个活动有用途;开放世界下是「选项」不是「任务」)
- **职业阶梯**: 打工分等级(杂工 0.5 币/分 → 职员 1 → 经理 2),晋升条件=累计学习时长。学习从纯亏变投资
- **资产阶梯**: 激活已有 `buy_property`——买断公寓免房租、资产值入账。金币从消耗品变资本
- **属性成长**(可选,roguelike 味,暂缓): 健身提体力上限、学习提经验速率

### 4.3 目标层(北极星+叙事)
- **繁荣分**(见 §5): 生涯账本,可结算可排行
- **人生事件记录**: 里程碑写入角色生涯(首次买房/晋升/濒死获救/结识挚友)——原「成就清单」在开放世界下的形态: 不做任务引导,做生涯记录
- **观察侧故事流**: 现有 event bus(activity.finished 等)→ agent 人生日更摘要。观察价值高、实现成本低

## 5. 繁荣分(life score)v1 定稿

- 形态: **每角色生涯账本**,只增不减(死亡扣减除外);纯服务端计算,快照可读。
- 组成:
  1. **生存质量流(v1 唯一组成)**: 每游戏分钟 `score += happiness / 1440`——解释性极强: 繁荣分 ≈ 累计「等效幸福天」(幸福 80 活一天 ≈ +80 分,幸福 100 活一天 = +100 分)
  2. 里程碑(v1 不做): 一次性事件固定分值(买房/晋升/挚友/濒死获救…),随社交/职业阶梯补
  3. 死亡扣减: 死亡时 `score ×= 0.8`(方案 B,见 §7)
- 设计原则:
  - **公式透明可解释**——LLM agent 必须能推理「做什么涨分」;分值随快照下发
  - **不干预世界规则**——它是读数不是裁判,不搞「分数低触发惩罚」
  - 人手玩同样成立(先于人手玩就有反馈),为 M4+ 效用函数打地基

## 6. 特质权重层 v0 草案(依赖 M4+ LLM 决策接入)

- 每角色一组特质维度(0~1): 雄心 / 享乐 / 宅 / 社交 / 节俭(维度集待定稿)。
- 特质影响: 活动选择倾向、繁荣分各项权重、消费倾向、(将来)社交相性(见社交设计)。
- 边界: **只改决策端,不改意图协议与世界规则**——世界对全员一致,公平且可观测。
- 生成: 出生随机/种子生成,M4+ 亦可由 LLM 在 agent 人设中声明。

## 7. 死亡与复活结算(2026-10-05 定稿: 方案 B 比例扣)

- 现状: 免费复活(惩罚过轻,导致奖励无味)。
- 定稿: 复活满状态 + **繁荣分 ×0.8(扣 20%)** + 短期虚弱 debuff(debuff 随平衡性调整另行落地,不阻塞账本)。
- 选 B 的理由: 固定扣存在套利——分越多死越「便宜」(900 分死一次仅 −5.5%,180 分死一次 −28%),隐性鼓励低分期摆烂;比例扣任意时点死亡代价对称,且贴「生涯账本」叙事: 活得越厚实,死亡的绝对损失越大。

## 8. 实施路线(2026-10-05 定稿)

1. **繁荣分账本 v1**(本轮,M3.6j): 质量流逐分钟累计 + 死亡 ×0.8 + 快照/面板可读。不依赖 agent 即有意义。
2. **社交 v1**(下一步): chat + 同场增益 + 相性(随机特质向量),详见 social-design.md。
3. **特质决策层**(M4+ 随 LLM 接入): 特质驱动活动选择,成为完整效用函数。
