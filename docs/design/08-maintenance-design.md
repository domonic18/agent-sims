# 世界维护系统设计(杂物/围栏破损 + 清洁工/修理工)

> 创建日期: 2026-10-05 · 用户脑暴定稿(损耗纯氛围+就业源;排期 M-G.4→M-G.3→M-G.5)
> 关联: 02-goal-design.md §4.2(岗位分层)、04-numerical-design.md §5.1/§5.3(数值权威)、06-worldgen-design.md §3④(围栏段数据化)

## 1. 目标与非目标

**目标**
1. 世界自损耗: 街道随机出现杂物、围栏随机破损——镇子"会变旧变脏",有生活感
2. 两个巡走岗位形成就业: 清洁工清杂物、修理工修围栏,按单结算
3. 完善职业分层: 无知识体力路线(清洁/杂工)→ 中阶(修理/服务员/售货员)→ 高阶(馆员/医生)

**非目标(用户 2026-10-05 定稿)**
- **损耗无数值后果**: 不清理只是视觉脏乱,不扣幸福/不入繁荣分——岗位收入即全部动机
- 不做建筑内部损耗、不做 NPC 自动雇佣(远期池)

## 2. 损耗生成(server 定时)

- **杂物**: 每 60 游戏分钟 roll 一次,在道路/广场/公园随机可行走格 spawn 1 个,场上上限 12(超则跳过);外观从 sprite 池随机(3~5 种)
- **围栏破损**: 每 240 游戏分钟在围栏段注册表内随机 1 段转为破损,场上破损上限 4
- 生成率即岗位需求: 生成 < 单岗位清理能力(清洁工 ~40 单/日理论值),一岗即可维持镇容,多角色竞争则接单博弈

## 3. 世界实体与快照

- 新实体 **maintenance spot**: `{ id, kind: 'litter' | 'fence_damage', x, y, variant }`;随快照下发,完成作业即从快照移除
- **围栏段数据化(前置工程)**: 围栏现状只是客户端渲染装饰(公园北缘一排,server 无感知)——须把围栏段注册为数据实体(内置图清单+生成图公园模板同加),server 掌握段位置才能标记破损、修理工才有目标可寻
- 占位格语义: 杂物不阻塞行走(可踩过),破损围栏沿用地形阻塞现状(围栏本体不可走)

## 4. 作业模型(巡走岗位,与锚点岗位互补)

- 新意图 `work_task { characterId, targetId }`: server 校验目标存在 → 寻路前往 → 到位作业计时(杂物 15 分/围栏 30 分)→ 完成: 实体消失 + **按单结算**(时薪×作业时长)+ 事件日志
- 作业中走岗位净速率(04 §5.1);低体力(< 低体力线)拒绝接单;与锚点活动互斥(作业中不可 start_activity)
- **连续作业**: 面板开关,完成一单自动接最近下一单——客户端 go-and-do 合成(与购物到达接续同款),协议保持单发,Agent(M4)可按意图逐单驱动
- 与锚点岗位的分工: 锚点岗=按时上班(办公楼/餐厅…),巡走岗=按需出工(有损耗点才有活)

## 5. 素材需求(随 M-G.3 素材轮)

| 类别 | 内容 | 来源 |
|---|---|---|
| 杂物 sprite | 3~5 种(纸屑/落叶/垃圾袋…) | LimeZu 完整版 draft 池 trash 类挑选+校验 |
| 破损围栏 | 变体 1~2 档(倾斜/缺口) | 完好 fence tile 已有;变体挑选或裁切合成 |
| 作业姿态 | 弯腰挥扫/拧扳手(可选工具道具) | 与 M-G.3 坐姿素材(study/work/meal)同一角色表现帧工作包 |
| 作业反馈 | 尘土/星光小粒子(可选) | 后置打磨 |

素材未就绪期: 世界层用临时色块占位开发,世界模拟与渲染解耦,可先行走查逻辑闭环。

1. **世界层**: 围栏段数据化 → 损耗生成器 → 实体快照 → work_task 意图与结算(临时贴图可走查全链)
