# agent-sims 认知与人格演化设计(Cognition & Personality Design)

> 本文档是 **agent 认知分层、人格演化与行为接线**的设计权威:对 01-agent-design §4.5(固化)/§5(记忆系统)的系统性重评与增补。
> 出发点(用户 2026-10-08 定稿): **小镇 agent 要逐步形成自己的人格、有自己的感受,过往经历逐步影响行为**。对照该出发点,M5 梦境固化的现行实现被定性为「营销手段」——产物好看但与行为无关。本文重新划定目标架构、数据形态与落地路线。实现与本文冲突时,先改本文再改代码。
> 关联: 01-agent-design(世界运行/认知周期/记忆三因子)、03-social-design(亲和度数值)、02-goal-design(方针/目标)。

## 1. 出发点与评估基准

**出发点**(不可妥协的三条):
1. agent 逐步形成**自己的人格**——不是访谈一次性生成的静态卡,而是随经历缓慢演化的"我是谁"
2. agent 有**自己的感受**——情绪是主观状态,给记忆编码和决策上色,不是结算面板上的标量
3. **过往逐步影响行为**——昨天发生的事,能在今天的行为里观测到因果(哪怕间接)

**评估基准换轨**: 人格形成的唯一可信证据是**行为分化**——不同过往的 agent 对同一事件做出不同反应,且 agent 自己能解释为什么。因此验收从「面板看到某类条目」(营销指标)换成「行为对照实验」(§8)。

## 2. 现状评估(为什么说 M5 是营销手段)

对照出发点逐条盘点(代码证据,零猜测):

| # | 结构性缺口 | 现状证据 |

## 3. 目标架构: 认知分层梯子

```
L4 自我叙事 「我是谁,我在意什么」        ← 人格本体(周级缓变)
L3 关系模型 「TA 是个怎样的人,我对 TA 的看法」 ← 每熟人一份动态认知
L2 语义认知  「我总结出的规律/教训/看法」      ← 夜间固化的主产物
L1 情景记忆  「我经历了什么」                 ← 已有(事件流水)
L0 事件      世界发生了什么                   ← 已有(EventBus)
────────────────────────────────────────
L5 情绪      贯穿各层的上色状态(实时)         ← 横切,不占层
```

| 层级 | 内容 | 数据形态 | 现状 |
|---|---|---|---|
| L1 情景记忆 | 带重要度的主观经历流 | memories(type=event/dialogue) | ✅ 已有 |
| L2 语义认知 | 从经历总结的看法/教训/规律,第一人称 | memories(type=insight)+source_ids 溯源 | ❌ C1 |
| L3 关系模型 | 对每个熟人的叙事认知(印象/恩怨/期待) | impressions 新表(§4.2) | ❌ C1 |
| L4 自我叙事 | 「我是谁」的一段话+核心特质,缓慢演化 | persona.selfNarrative+版本链(§4.3) | ❌ C5 |
| L5 情绪 | valence+标签的脑内状态,实时衰减 | brain state mood(§4.4) | ❌ C2 |

**四条架构原则**:
1. **单向爬梯**: 认知只能从下层提炼(夜间固化/白天反思是唯一的上爬通道),上层不被直接写入——保证「认知有据可溯」
2. **上层慢变**: L1 实时、L2 每日、L3 交互后惰性、L4 周级/里程碑、L5 实时且快速衰减——人格稳定与经历影响的张力靠时间尺度分层解决
3. **人格=梯子顶端的稳定物**: L4 自我叙事 + L2/L3 中反复被巩固的部分;它不是新数据结构,而是梯子自然收敛的结果
4. **全员人可见**: 各层皆为自然语言 content(真相源),向量仅作检索索引(延续 01 §5.6 原则);记忆面板增层过滤,玩家可看「TA 对某人的印象」「TA 的自我叙事演化史」

## 4. 数据形态设计

### 4.1 L2 语义认知: memories 复用+溯源列

- **复用 memories 表**,type=insight(枚举已预留,零迁移);content=第一人称认知句(「苏晚总在我困难时搭把手,可以信任」「累倒的代价是整整一天干不了活,不值得」)
- 0005 迁移加 `source_ids jsonb`(情景记忆 id 数组,≤8 条)——认知必须溯源到具体经历,这是「过往影响行为」的审计链
- 检索与情景记忆**同池**(同一三因子排序): insight 通常 importance 较高(慢思考给定 6~9),自然在日计划证据里压过琐碎事件

### 4.2 L3 关系模型: impressions 新表

```
character_impressions: id, character_id(FK), about_id(FK characters),
                       content(text 第一人称印象), game_minutes, updated_at
                       UNIQUE(character_id, about_id)
```

- **为什么不进脑状态内存/jsonb**: 关系印象需要面板展示(「TA 怎么看苏晚」)、trace 引用、存档恢复三路消费,独立表最直白;行数=角色×熟人上限(12×12),可忽略
- **写路径**: 仅两条——夜间固化对当日互动者产印象增量(§5);重大交互(结交/翻脸/获救)即时惰性更新
- affinity 标量保留(数值层,03-social-design 管辖),印象是它的**叙事解释**: 数值说「多熟」,印象说「为什么熟/值不值得」

### 4.3 L4 自我叙事: persona 扩展+版本链

- characters.persona jsonb 增 `selfNarrative: { text: string, traits: string[], version: number, updatedAtGameMinutes: number }`
- 修订规则(§6): 旧版整体入 `persona.narrativeHistory[]`(环形保留最近 10 版)——「人格演化史」人可回看,直播可观测
- 未初始化时(老角色/新角色)回落现有人设卡 bio——兼容零迁移成本

### 4.4 L5 情绪: brain state mood

- `agents/cognition.ts` 增 `mood: { valence: number(-1~1), labels: string[], since: number }`,按角色 Map+落库(§3.2 脑状态外置惯例)
- 更新: 事件即时打标(被拒/倒下→valence↓;结交/获救/做出成品→↑),由**规则映射**零模型;自然衰减回中性(半衰期≈4 游戏时)
- **不进快照不下发**(脑内状态,玩家经面板/访谈间接观测)——保持世界侧零感知

## 5. 固化管线 v2: 睡眠=爬梯工厂

改造 memory-consolidation.ts → 认知固化器(dream 降级为副产品):

- **触发不变**: sleep.settled(睡饱)、上一清醒日未固化记忆 top16、同角色单飞
- **慢思考一次调用,产出结构化 JSON**(替代现纯 dream 数组):

```json
{
  "dreams":    [{ "content": "…", "importance": 1-10 }],        // 0~3 条,氛围保留
  "insights":  [{ "content": "…", "importance": 1-10,
                  "sources": [记忆原文引用] }],                  // 0~3 条,认知主产物
  "relations": [{ "about": "苏晚", "content": "…" }]            // 对当日互动者的印象增量
}
```

- **写回次序**: dreams→type=dream;insights→type=insight 带 source_ids;relations→impressions 定点 upsert;全部成功才打 consolidatedAt(失败语义沿用: 静默+次夜重试)
- **白天反思补线**(01 §4.5 欠账): importance 累计阈值触发,复用同一产出管线(去掉 dream 段)——白天大事件不必等到夜里才沉淀
- **自我叙事不在每夜动**(防漂移,见 §6);mood 不进固化(实时态)
- **成本**: 每角色每晚仍 1 次 slow 调用(与现持平);输出 token 上限略升(≈+200),按现行居民规模可忽略

## 6. 自我叙事演化(L4): 人格的缓变机制

- **触发**(二选一先到): ①每 7 个游戏日例行;②里程碑事件(首次倒下被救/首次挚友/首次买断房产/缺觉惩罚满 3 次…)
- **机制**: 慢思考读「当前 selfNarrative+近 7 日 insights+重要 relations」→ 产出修订版(第一人称 ≤200 字)+特质微调
- **防漂移双闸**: ①单次修订幅度约束(prompt 明令: 只允许基于给定认知微调,不得推翻既有核心特质);②版本链留档+每次修订写一条 insight 记忆(「我对自己的看法变了: …」)——演化本身可审计
- 新角色: 未初始化时以人设卡 bio 自动兜底建 version 1(不烧模型);管理员可经面板 light 槽生成叙事草稿(原「访谈生成」方案随访谈退役调整为面板按钮,2026-10-09 C5 落地定稿;里程碑实际实现三键: first_rescued/first_friend/sleep_debt_3,买断房产无独立事件源暂缺)

## 7. 决策接线 v2: 事件响应与社交通路

初版 §7 只有「prompt 证据注入+规则调权」——默认消费主体是日计划与台词,漏掉了两个结构性空洞(用户 2026-10-08 两问): 计划执行器木讷(事件进不了忙角色的决策)、社交行为通路不存在。本节按 v2 重写。

### 7.1 事件响应层(问题1 的答案)

**现行缺陷**(§2 #7): 三判定函数共用忙守卫——活动/路径上的角色对一切事件零反应;`scheduler.onEvent` 对事件同构处理,jev 不读事件内容。问题不是「要不要调 LLM 没设计好」,而是**事件根本进不了忙碌角色的决策**。

**目标结构**: 在感知与决策之间插一道**事件分级(triage)**,①②③④全规则零模型,只有歧义案进入 LLM 评估:

```
事件 → ①相关性门 → ②强度门 → ③可打断性 → ④分级处置 → (仅歧义案)⑤中断评估
```

| 关卡 | 规则 | 消化方式 |
|---|---|---|
| ①相关性门 | 事件主体是我/涉及我的熟人/发生在我所在或目的地格子 | 不相关→忽略(不惊动任何判定层) |
| ②强度门 | importance≥6 才可能打断当前块;<6 只允许 rule 吸纳 | 低强度→忽略或 rule |
| ③可打断性 | 活动声明容忍度: sleep/meal=不可打断,study/work=低(仅高强度事件),stroll/idle=高 | 不可打断→排「事后处理」 |
| ④分级处置 | 忽略 / 规则吸纳 / 歧义案→⑤ / 计划失效→重规划 | 处置动作 |
| ⑤中断评估 | systemOne choice「继续当前块 vs 响应事件」,题面带事件语义+当前块描述+相关认知(L2/L3/mood) | LLM 一词判定,与 jev 同成本级 |

**响应动作注册制**: 事件类型→响应动作的映射表(如 `获救→感谢对话、合作邀约→按对 TA 的印象 accept/reject`),由各业务系统注册,决策层查表执行——scheduler 不硬编码业务语义。

**预算护栏**(防中断风暴): 每角色每日中断评估≤4 次+30 游戏分冷却+睡眠一律不打断+同一事件不重复评估;全程 trace 可审计。

**中断后回计划**: 响应完事件,跳过被中断块,从下一块边界衔接原计划——不整日重规划(计划是脚手架不是剧本,这是「木讷」与「失序」之间的平衡点)。

**成本结论**: ~90% 事件被①②③规则门消化,LLM 调用仅新增预算内⑤(systemOne ≤4 次/角色/日)。

### 7.2 社交行为通路(问题2 的答案)

**现行缺陷**(§2 #8): 三层都缺——动作空间无社交项、动机模型缺失(affinity 只被动记录)、记忆未消费。**只把记忆建好不会长出社交行为,通路本身不存在**;诊断结论: 是机制设计问题,记忆系统未应用只是其中一环。

**四段通路**(动机→触发→执行→回路),每段只补缺口不推翻:

| 段 | 现状 | 补齐方案 | 成本 |
|---|---|---|---|
| 动机 | affinity 被动记录 | **动机规则引擎**(零模型): 基础欲望=affinity≥50 且冷却已过;调节项=久未聊欲望↑(熟悉度衰减)、情境加成(同桌工作/同场活动)、情绪加成(valence>0) | 0 |
| 触发 | 全仓无自主 chat | 空闲角色: 社交动机作为候选进 jev(与地点候选同池竞争);忙碌角色: 显著社交事件经 §7.1 分级门触发 | 0 |
| 执行 | 仅玩家发起有台词 | chat 意图走既有 light 调用,prompt 注入「你对 TA 的印象」+「你现在的感受」 | 0 新增频次 |
| 回路 | 对话留档无消费 | 对话记忆→夜间固化 relations(§5)→关系印象→下次动机——闭环 | 0(C1 已建) |

**计划词汇表**: PLAN_ACTIVITY_IDS 增 `socialize`——「找苏晚聊聊天」可作为计划块,日计划 prompt 增社交候选段。(D3 起随更: DayPlan 刚性日程退役为弹性意图 wants,socialize 作为 want 活动保留同一语义——社交动机仍走本节四段通路,意图载体由计划块变为 want;另 D1 补动机段前置缺口: 初识者 familiarity=0 的冷启动死锁由共处破冰通道解,见 03-social-design §8。)

**设计红线**: 社交不新增 LLM 调用频次——chat 复用现行 light 台词调用;「想不想聊天」由规则引擎回答,不问模型。

### 7.5 统一意图架构修订(E6,2026-10-10 定稿)

C/D 系列落地后系统长出**五种行为来源**(slow wants/jev/社交动机引擎/rule/triage respond),其中四种绕过意图存储直接执行——症状一致: 到达即死(E5 验收 stroll=0、sell 死在门口、走近朋友被截断的共同根因)、trace 只剩一行 react 不可审计、被 want 层截胡。E6 统一为「双系统产欲、单通道执行」,总设计见 01-agent-design §3.3;对本节各段的修订:

- **§7.1 修订(E6.2-S2 落地)**: ④处置的 respond/defer 产物从「注册表动作直执」改为「**事件 want**」(writeEventWant: origin=event,带 urgency 与 `EVENT_WANT_TTL_MINUTES 60` 半衰——defer 队列删除,溶解为冲动消退;**写入不打断任何人**,忙碌角色由 wantSelect 闲时评分调度,空闲角色写后即时 kick 择条;同活动+同人在途 want 去重;无当日意图容器静默消退);抢占由评分裁决(事件 want urgency vs doing want),活动容忍度门照旧为硬闸;⑤中断评估照旧,其 respond 答案=写事件 want 而非直接执行。响应注册表保留,产出从 intent 改为「事件语义→事件 want」映射(救人→rescue want,urgency 由好感加权;获救道谢→socialize want 走两阶段会合;救援 want 执行=rescueExecution 到场即完成,目标已起/不在当场收口)。②强度门由静态表升级为预算内 jev score 评价**挪至 S3**(静态表 EVENT_STRENGTH 照旧)
- **rule→驱力(E6.2-S2 落地)**: 五级直执链(饥饿/租金/贫困/直采/困倦)改**驱力生成器** driveDecide——恒稳态压力→urgency 写 drive want(饥饿族按 E1 逃生梯互斥: 能买→eat,买不到→earn,也无岗→forage;sleep 独立评估可并存),执行逻辑自旧 rule 逐字平移进 wantSelect **驱力专属分支** driveExecution(eat/earn/forage/sleep 伪活动词汇表,不查活动定义;豁免知识门槛/体力闸/rest 守卫——生存压力天然优先),驱力生命周期双保险: 压力缓解 driveSatisfied 主动收口 done(调度泵 15 分块巡检)+wantSelect 惰性收口(doneWantIds);通道消失废弃改道(写侧逃生梯重评)。rent 保持即时结算——账单不是行为,唯一保留的直执 rule
- **§7.2 修订(E6.1 生效)**: 动机引擎归入 want 通路——「动机」段降为驱力生成器(欲望分→socialize want,urgency 映射,封顶剔除/冷却/日预算照旧在动机段把门),「触发」段 jev 池候选照旧但产物=冲动 want,「执行」段由 wantSelect socialize 分支承担(远处 move_to 两段式走到身边,贴身触发 light 台词双调用);**共处破冰(acquaintanceStep)属感知/数值通道,不属决策层,保持不动**。「想不想聊天由规则引擎回答,不问模型」红线不变——动机只产欲望分,LLM 不参与点火判定
- **§7.2 执行段修订(E6.2-S1 生效,两阶段会合协议=event→want 通道首个消费者)**: 贴身 chatWith 不再直接烧模型,拆**召唤→应答→生成**三拍——召唤(零模型): 写对方 event want(origin=event「回应X的搭话」,urgency=`SOCIAL_SUMMON_URGENCY 0.9` 赴约档,半衰 `SOCIAL_SUMMON_TTL_MINUTES 90`)+建会合台账即返回;应答=agent 自裁: 对方 wantSelect 评分竞争(可被更高分让位=婉拒,零成本),执行链即时 kick(贴身空闲即应答即 commit),应答方成为生成执行者(气泡/lines/印象归其名下);生成(唯一烧模型口): 双方就位(贴身+对方静置)才进——共在校验从生成后前移到生成前,E6.1 观察的走散空烧通道(2h 133 次=62% 生成丢弃)随之闭合。配套: wantSelect socialize 贴身分支三门控(生成在途静候/我召唤未应答不重复点火/落地短冷却),onPath 门控退役(走路中可被召唤,走完当前步应答);生成护栏升对级+角色级(一人只进一场);rendezvousSweep 超时回收(give-up 120 分,零 token);主动社交记账归发起方。机制细节见 03-social-design §8
- **§4.4 修订(E6.2-S3 规划)**: mood 冲量来源由「规则映射」升级为**评价式**(预算内 jev score 题:「这件事对你来说多糟/多好」),同一事件因人(印象/记忆)因状态(valence/数值)冲击分化——评价理论(OCC/EMA)的 jev 化,memory importance 打分(memory-writer.ts)已是同款先例;规则映射表降级为预算外/低冲击兜底
- **习惯化(S2→S1 下沉)与内在言语**列为观察项:E6.2 长跑数据说话后再决定,当前不排期(防过度设计)
- **成本红线不变**: 新增评估调用全部在预算护栏内;E6.1/E6.2-S1/E6.2-S2 均零新增 LLM 调用(会合协议反而消灭走散空烧)

## 8. 验收标准: 行为对照实验

营销指标退役。C 系列各步验收以下列为准(全部经 trace/面板可取证):

| 维度 | 实验 | 通过判据 |
|---|---|---|
| 分化性 | 两个不同过往的 agent 遇同一事件(如都被苏晚请求合作,一个被坑过一个受过恩惠) | 决策相反或明显不同,且 trace 证据引用各自的 insight/印象 |
| 一致性 | 追问任意 react 决策的理由 | 能从 trace 检索证据定位到具体记忆/认知条目(content 原文) |
| 演化性 | 同一 agent 首周 vs 第 N 周对同类事件反应 | 反应不同,narrative/insight 前后版本可对照出变化点 |
| 恢复性 | 世界重启/角色复活 | 自我叙事/关系印象/insight 全部保留(存档链路覆盖) |
| 情绪可见 | 制造大起大落事件 | 访谈语气/台词色彩随 mood 变化,面板可查 mood 历史 |

## 9. 路线: C 系列(Cognition,串行小步)

**排期定稿**(用户 2026-10-08): NPC 体系(M6)延后,C 系列优先——先把 agent 的自主运行机制搭起来。

| 子阶段 | 规模 | 内容 | 验收抓手 |
|---|---|---|---|
| C1 固化管线 v2+数据地基 | M~L | 0005 迁移(source_ids+impressions 表);memory-consolidation.ts 改造(§5 结构化产出);白天反思补线;记忆面板增「洞察/印象」查看 | 次晨面板见 insight(溯源可点)+关系印象更新;dream 仍产出 |
| C2 情绪主观化 | S~M | brain state mood(§4.4): 事件打标规则+衰减+落库;访谈 prompt 注入;面板 mood 历史 | 大起大落事件后访谈语气可感变化 |
| C3 事件响应层 | L | 活动容忍度声明+事件分级门(§7.1)+响应动作注册表+中断评估(systemOne)+预算护栏;trace 增分级记录 | 忙碌角色对显著事件受控反应;trace 可答「为何理会/不理会」;预算生效(日≤4 次) |
| C4 社交行为闭环 | L | 四段通路(§7.2): 动机规则引擎+jev 社交候选+chat 意图接线+PLAN 增 socialize+固化回路;对话 prompt 双段注入 | 自治角色间出现自主对话;台词引用共同经历;关系印象越聊越具体 |

排序依据: C1 产认知(地基)→ C2 上色(独立小步)→ C3 长出**对世界的反应**(事件不再穿身而过)→ C4 长出**对人的反应**(社交自发出现)→ C5 人格收口。C3/C4 是出发点验证的关键步——**在此之前,一切仍是记忆系统;之后,才是人格**。

依赖与风险:
- **中断风暴**: §7.1 四重护栏(评估上限/冷却/睡眠豁免/同事件去重),trace 全程可审计
- **社交过度**: 动机引擎带冷却(同人每小时≤1 次)与每日社交预算;先观测再调参
- **LLM 编造认知**: insights 必须引用 sources 原文,无 source 支持的认知丢弃;关系印象限定当日互动对象白名单
- **人格漂移**: §6 双闸+版本链;修订频率上限(周级)
- **token 成本**: 固化与台词频次零新增;新增仅预算内中断评估;上量后按 token_usage 面板观测
- **老角色兼容**: 无 narrative/impression 时回落现行为(人设卡 bio/无印象),渐进填充
