# agent-sims 数值规划(Numerical Design)

> 本文档是游戏数值的**唯一权威来源**(single source of truth)。
> 代码中的常量(`@sims/shared` 内容定义、`apps/server/src/config/balance.ts`)与本文表格一一对应;
> **调整数值须先改本文档再改代码**,并在表格后追加一行变更记录。
> 定稿: M3.6g(2026-10-04),首次系统性规划;2026-10-07 数值体系重构(体力/健康解耦+幸福度→得分)。

## 1. 设计总则

- **一日预算平衡**: 以"游戏日=1440 分钟"为单位演算,正常作息(睡眠 8h+工作 8h+三餐杂余)体力净增为正(留余量给健身/学习等高耗活动),不睡觉则 1 个工作日内跌入低体力区——用数值压力逼出"回家睡觉/吃饭"的真实行为,而不靠硬性规则。
- **净速率模型**: 活动数值即**净速率**(已含该活动期间的代谢),活动中不再叠加基础代谢;只有**待机**(无活动)走基础代谢衰减。数值语义清晰,Agent(M4)可直接读表规划。
- **三层量表各司其职(2026-10-07 定稿)**: 体力=行动预算(归零**虚脱**不死亡);健康(仅 survival)=**唯一死亡闸门**(归零重伤休整);得分=事件直加单调递增的成就记录(无阈值后果、不衰减)。

### 2.2 一日预算演算(验证平衡)

典型作息(睡眠 8h+打工 8h+就餐 1h+散步 1h+待机 6h):

```
+168(睡) -72(工) +3(餐) -2.4(散) -7.2(待) = +89 / 天
```

净 +89 的富余即"健康生活"的奖励空间——健身 1h(-24)+学习 1h(-7.2)后仍为正。打工按统一 -0.15 口径演算(§5.1,档位取消后全岗位一致)。
反例(不睡觉,全天打工+待机): -144-9.6 ≈ **-154/天** → 从 100 计约 **0.65 个工作日**即跌至低体力线。

### 2.3 阈值与生死(2026-10-07 重写: 体力归零虚脱,健康唯一死亡闸门)

| 阈值 | 值 | 效果 |
|---|---|---|
| 低体力线 | energy ≤ **20** | 仅可基础活动(rest/stroll/meal),高强度拒绝;survival 下跌破饥饿线健康缓降(§5.5) |
| 危急线 | energy ≤ **5** | 体力条红色(UI) |
| **虚脱** | energy = **0** | **不再死亡**(与健康的生死语义解耦)——表现与解除按模式分流(下表) |
| **健康归零(仅 survival)** | health = **0** | **唯一死亡闸门** → 重伤休整(幽灵态+救治窗口 1440 分);救治满状态复活 / 超时苏醒 health/energy=30(§5.5) |

**体力归零→虚脱(模式分流)**:

| 模式 | 语义 | 机制 |
|---|---|---|
| survival | **原地虚脱**: 倒地待救,可被喂食/安排就地休息恢复(energy>0 即解除);期间饥饿线照跑(=0 持续扣健康)→ 可能滑向重伤休整,硬核无兜底 | 快照 `collapsed=true`(alive 不变);意图门禁只放行 sleep/rest/eat |
| growth(allowDeath=true 默认) | **累倒送医**: 复用幽灵态+救治窗口骨架——窗口 1440 分内医生救治单施救满状态复活(energy=100)**免除扣分**;超时自动苏醒挂起扣分生效 | alive=false、`diedAtGameMinutes` 挂起;医生岗保留(M-G.5) |
| growth(allowDeath=false,relaxed) | 不挂窗口——原地虚脱(卡能量不进流程,类比 survival 卡 health=1 结构) | 可自行休息/进食恢复,无扣分 |

- 救治窗口 REVIVE_WINDOW_MINUTES=1440;累倒超时扣分 **SCORE_WAKE_DEDUCTION=0.2**(仅 growth 送医窗口超时;survival 重伤超时苏醒不扣,§5.5)。
- /debug 与 /lab 复活按钮保留开发者兜底,视同救治(免扣)。
- 代码: `balance.ts` LOW_ENERGY_THRESHOLD / REVIVE_ENERGY / SCORE_WAKE_DEDUCTION;`simulation.ts` `_checkDeath` 模式分流、`character.ts` collapsed 门禁与 `reviveCharacter`。

### 2.4 睡眠机制(M-G.2 落地,2026-10-06)

**设计原则: 睡觉行为由玩家触发,系统一律不代劳**——不做自动入睡、不做作息开关(server/web 均零自主行为),只靠缺觉惩罚的数值压力倒逼玩家安排作息(呼应 §1「不靠硬性规则」哲学)。

| 项 | 值 | 说明 |
|---|---|---|
| sleep 活动 | **480 分**自然醒 | 独立活动(非 rest),速率复用床档 +0.35;8h 恰 +168 回满;中断可续睡 |
| 床锚点 | 须**自家**床位 | 床家具双服务 rest/sleep(地图数据零改动,`furnitureServesActivity` 谓词泛化);须租约有效,他人床/公园长椅不可睡 |
| 睡眠窗口 | 22:00 ~ 06:00 | 复用夜间参数 NIGHT_START(1320)/NIGHT_END(360),跨零点;窗口内每睡 1 分计入角色账本 |
| 缺觉阈值 | **SLEEP_MIN_MINUTES=240**(4h) | 每日 06:00 结算: 窗口累计 <240 分 → 挂缺觉 1440 分(次日 06:00 到期)并发 `sleep.debt_applied`;结算后账本无条件清零 |
| 缺觉系数 | **SLEEP_DEBT_MULTIPLIER=0.7** | 仅罚**正收益**: 正金币(工时/按单)/正得分/采集与制作产出 floor(count×0.7,单件产出可能为 0——料不退,有意诚实);体力消耗、负项不动 |
| UI | 😪 徽标 | 缺觉日角色状态区显示;睡眠中显「😴 睡眠 x/480 · 本夜 y 分」 |

代码: `packages/shared/src/furniture.ts`(谓词/SLEEP_ANCHOR_KINDS)、`apps/server/src/world/simulation.ts`(_settleSleep/_inSleepWindow/_debtFactor)、`balance.ts`(SLEEP_MIN_MINUTES/SLEEP_DEBT_MULTIPLIER,Lab 可热调,下一 06:00 结算生效)。

### 2.5 得分体系(score,2026-10-07 新增,替代幸福度)

**设计原则: 事件直加、单调递增**——得分是成就记录而非运营量表: 无阈值后果、无待机衰减、只在事件发生时入账;唯一扣分源=累倒送医超时(§2.3)。内部浮点累加、快照取整显示。

| 得分源 | 规则 | 数值 |
|---|---|---|
| 正向活动 | effects.score 速率×实际进行分钟,每分钟入账(中断不回滚,取消也按已进行分钟计) | 健身 +0.35/分·散步 +0.15/分·就餐 +0.20/分·制作 +0.05/分(§2.1) |
| 食物 | 吃下即入账,effects.score 1:1 | 蛋糕 +10/寿司 +5/牛奶 +3/浆果派 +4…(§3.1/§5.4) |
| 聊天 | `max(0, CHAT_SCORE×递减档×相性)` 取整,双向 | CHAT_SCORE=2(§6.2);相性为负不扣分 |
| 缺觉 | 正得分 ×SLEEP_DEBT_MULTIPLIER(0.7),与正金币/产出同罚 | §2.4 |
| **扣分唯一源** | growth 累倒送医窗口超时苏醒 | score ×(1−SCORE_WAKE_DEDUCTION=0.2)(§2.3) |

- **零分源**: 工作/学习/服务/采集(原负幸福归 0——劳动不因无趣扣分)、休息/睡眠、待机(原待机衰减/同场增益删除)。
- 原「繁荣分 lifeScore」(=happiness/DAY_MINUTES 逐分钟累积)机制删除,由本节事件直加取代;协议字段 `lifeScore` 更名 `score`。
- 代码: `character.ts`(score 字段/addScore 入账)、`activity.ts`(settle 逐分钟)、`social.ts`(CHAT_SCORE)、`snapshot.ts`(取整)。

### 3.3 容量机制

| 容器 | 体积上限 | 说明 |
|---|---|---|
| **背包**(随身) | **8** | 买入即入背包;任意地点可吃;≈4~8 份食物 |
| **冰箱**(家中) | **30** | 须在家(自有或租约有效)存/取;≈一周口粮 |

## 5. 经济(沿用 M3.2/M3.3 定稿,此处汇总)

### 5.1 职业与知识(2026-10-06 修订:类别平行模型,原四档双梯度取消)

### 5.5 生存健康数值(M-S/S1,2026-10-07,仅 gameType=survival 生效;数值权威)

和平期压力源=饥饿(design/07 §4):体力跌破饥饿线持续损耗健康,吃回康复线自然恢复;**健康归零=重伤休整**(角色不死,复用 M-G.5 幽灵态+救治窗口骨架)。体力归零不再触发重伤——是**原地虚脱**(§2.3: 可喂食/休息恢复,期间饥饿线照跑,故虚脱是滑向重伤的压力入口)。

| 参数(BALANCE 热调) | 默认 | 说明 |
|---|---|---|
| SURVIVAL_HUNGER_ENERGY_LINE | 20 | 饥饿线:体力 < 该值每分钟 health -0.03 |
| SURVIVAL_HEALTH_DECAY_PER_MIN | 0.03 | 饥饿健康损耗/分(约 55 游戏小时由满耗尽) |
| SURVIVAL_HEALTH_RECOVER_LINE | 60 | 康复线:体力 ≥ 该值每分钟 health +0.02 |
| SURVIVAL_HEALTH_RECOVER_PER_MIN | 0.02 | 康复回复/分 |
| SURVIVAL_INJURY_REVIVE_HEALTH | 30 | 重伤超时苏醒的恢复线(health/energy=30) |

- **重伤休整结算**: health≤0 → 幽灵态(存活=false,救治窗口 24 游戏时 REVIVE_WINDOW 同 growth);窗口内医生救治=满状态复活(health=100,医生岗在生存模式仍有价值);超时自动苏醒=health/energy 回 30、**score 不扣**(软惩罚;growth 累倒超时扣 ×0.8,§2.3)
- **关闭死亡(allowDeath=false)**: survival 下健康同步卡 1 不入重伤;虚脱置位不受 allowDeath 影响(原地虚脱是物理事实,非死亡流程)
- **growth 零回归**: health 字段恒 100 不结算;快照 characters[].health 仅 survival 有显示意义(前端健康条按 gameType 分流)
- 代码: `applyHealthTick`(character.ts,逐分钟步进)、`_checkDeath/_checkReviveWindow`(simulation.ts 模式分流)、`reviveCharacter` injuryWake 分支

### 5.6 需求驱动的生产经济(E1,2026-10-09,数值权威)

E1 激活采集/制作/服务岗的消费通路,食物供给从「商店初始存量售罄即止」改为**采集→卖货→商店有货→他人购买**的镇内循环,自动补货降为兜底:

| 参数(BALANCE 热调) | 值 | 说明 |
|---|---|---|
| SHOP_RESTOCK_DAILY | **1**(原 3) | 日翻转每品类补货份数,封顶初始货架量;只防死锁,主供给靠采集/制作 |
| SELL_RATE | **0.6** | 商店收购价 = 售价 × 0.6(`sell_item {characterId,itemId,count}`,校验在场商店+背包足量,库存 +1 金币入袋;web 物品弹层「卖」钮同通道) |
| POVERTY_COIN_LINE | **12** | 贫困线: coins < 12 触发 rulePoverty 生存阀 |
| POVERTY_MIN_ENERGY | **45** | rulePoverty 体力下限(低于则交棒休息/觅食,不做无效打工) |

- **生存阀三 rule(E1,保人设选岗)**: `rulePoverty`(贫困+体力≥45+空闲 → 岗位池=[服务岗(知识够)/work] 按 activityBias 排序取最高,两段式执行);`ruleForage`(体力≤20+背包无食+买不起或店空 → 最近可食节点 work_task 直采逃生门);`ruleHunger` 让行(店空/没钱返 null 交棒);`ruleSleepy` 租约感知(无有效租约 → park 长椅 rest,消灭撞床循环)。
- 供货循环意义: 采集物可卖(`SELL_RATE` 折价)→ 商店货架有货 → 他人可购 → 收入再流通;`SHOP_RESTOCK_DAILY=1` 保证极端断供次日仍能解冻。
- 验收指标(见 01-development-plan E 系列): 分工分化 ≥3 种收入活动在跑、采集卖货 ≥1 次/日(稳定后)。

## 6. 社交(social-design 定稿,M3.6l)

### 6.1 二轴有向关系(A→B 与 B→A 独立两条)

### 6.2 chat 闲聊收益

| 参数 | 值 | 说明 |
|---|---|---|
| CHAT_FAMILIARITY_GAIN | 6 | ×当日递减,只涨主动方 |
| CHAT_AFFINITY_BASE | 4 | ×相性系数×当日递减,双向 |
| CHAT_SCORE | 2 | ×递减档×相性后 `max(0,·)` 取整,双方(相性为负不扣分,§2.5) |
| CHAT_DAILY_GAINED | **6** | 每游戏日**有收益**的次数;超出不拒绝、收益为 0(社交不设硬上限,Agent 间高频交流) |
| CHAT_DECAY_STEPS | 1 / 0.6 / 0.4 / 0.3 / 0.2 / 0.1 | 第 n 次 ×STEPS[n-1];超出档位 ×0;Σ=2.6 |

- 前提: 双方存活、非同一人、同处一地(曼哈顿 ≤ SOCIAL_CHAT_DISTANCE=2)。
- 相性系数 compatibility = 1.4 − 1.8×五维平均绝对差(特质 0~1: 雄心/享乐/宅/社交/节俭);
  完全同型 ×1.4,完全相反 ×−0.4(反感跌)。
- **不设硬上限**: 第 7 次起照常对话(气泡/日志照发,content 照常),但熟悉/好感/得分增益全为 0
  ——防刷靠收益归零而非拒绝,适配 M4 Agent 高频社交。
- 节奏(6 次聊满): 熟悉度日净 +6×2.6−1 ≈ **+14.6/天** → 当天点头之交,朋友约第 2~3 天,
  挚友(相性 1.4)约第 4~5 天(好感线 65 为主门槛)。
