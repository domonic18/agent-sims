## 1. 项目定位

像素风模拟人生网页游戏:玩家在模拟城市中学习/工作/生活,体力值+幸福值驱动活动反馈,打工赚金币用于消费、租房、买房、买家具;核心差异化——角色可随时托管给 AI Agent 代玩、也可随时接管,Agent 是玩家"人格的衍生",社交行为符合玩家人设,玩家之间可文字交流。

**目标用户**: AI Agent 技术爱好者与独立游戏玩家——想看"自己的 AI 分身怎么生活"的玩家。

**核心价值**:
1. 开源界首个「可托管 Agent 代玩的像素模拟人生」(调研已验证生态空白,见 research/01)
2. Agent 决策完全可见、可解释、符合人设——不是挂机脚本,是"你的分身在生活"
3. 离线不中断:玩家下线后 Agent 继续生活,关键事件经飞书推送(竞品均无)

### 1.1 两条根本原则(全项目最高约束)

| # | 原则 | 含义 |
|---|------|------|
| 1 | **人格衍生高于一切** | Agent 的每个决策必须可解释、可追溯、符合玩家人设。托管不是挂机脚本——玩家应能从 Agent 的行为中认出"自己"。决策可见性(见 §3.3)是需求,不是优化项 |
| 2 | **成本分级是硬约束** | 慢思考 LLM + 快反应 Jev(System One)双模型协作,架构级设计而非后期优化。已在 ai-invest-assisstant 实践验证该模式有效。成本预算参数在技术方案阶段定,但分级设计一期必须落地 |

## 2. 核心玩法与体验

### 2.1 一期单人 + 参观模式

- 一期为单人游戏(单玩家单角色):仅一名玩家可操作自己的角色;"玩家之间可文字交流"中的对方即 NPC(Agent)
- **参观模式(用户定稿 v1.3)**: 其他玩家不参与游玩,但可**只读参观**小镇运行——观看世界实时画面、角色行动与决策气泡、记忆/日程面板;**不可操作角色、不可与 NPC 对话、不对世界产生任何影响**;无需账号
- 多人参与游玩明确不做(见 §7);参观模式为后置多人游玩期的前置验证

### 2.2 托管/接管(核心差异化)

- **操作权原子切换**: 自己操作 ⇄ 托管,状态不丢失、立即生效;架构上 Agent 与玩家走同一套意图指令层,仅指令来源不同(见 research/01 §2 路线 A)
- **托管模式**(用户定稿:以 b 为主,a 为辅):
  - **a. 全托管**: Agent 完全自主决策
  - **b. 生活方针托管(主推)**: 玩家设定生活方针(如"本期攒钱买房""多社交""专注学习"),Agent 在方针约束下自主安排日程
- 切换期间游戏世界持续运行

### 2.3 Agent 决策可见

| 层级 | 内容 | 形式 |
|------|------|------|
| 即时层 | 当前动作+决策理由 | 角色头顶行动气泡(如"去上班,因为要攒买房钱") |
| 回顾层 | 记忆/日程 | 记忆面板(事件/洞察/梦境/对话四类条目)、日程面板随时查看;NPC 记忆点击角色只读查看 |

### 2.4 人设建立: 对话式访谈

- 新玩家经 5~8 个问题的对话式访谈建立初始人设卡(性格/兴趣/目标/说话风格),非表单填写
- 人设随行为持续修正(Agent 观察玩家操作,更新人设卡)——"人格衍生"随游玩越来越像本人

### 2.5 暂停/恢复

- 点击暂停按钮,整个游戏世界进入暂停状态:时间流速停止、玩家 Agent/核心 NPC/背景NPC 全部模拟冻结、离线降频模拟一并暂停
- 点击恢复按钮,从暂停时刻继续运行,状态不丢失、无跳变
- 暂停优先级高于一切模拟(含 §4 离线持续生活):暂停状态下玩家离线再重进,世界仍处于暂停态,需手动恢复才继续

### 2.6 后台管理(用户定稿 v1.2;模块表 2026-10-05 复核扩充)

系统提供后台管理(一期单人,管理员即玩家本人):

| 模块 | 能力 |
|------|------|
| 模型与 API-Key | 慢思考 LLM 与快反应 Jev 的选型、接入参数(BASE_URL/模型名)、API-Key 的增删改查;**取代环境变量配置**,保存后游戏调用即时生效 |
| 世界管理 | 创建世界(agent 人数/人物配置)、暂停/时间流速控制;v1.5 起创建重构为分步向导(§2.9) |
| Token 用量统计 | 按槽位/任务类型的消耗分布视图;价格表接入后含成本(cost 字段已预留) |
| 系统参数 | 非密钥类运行参数的查看与修改 |
| 账户安全 | 管理员密码修改 |
| 素材管理 | v1.5 新增:树形分类+放大校验+发布链路(§2.8) |

- 环境变量仅保留非密钥类运行配置(端口/数据库连接等)
- 后台访问控制已定: 登录鉴权 scrypt+HMAC token(12h),见 §10 决策记录

### 2.7 睡眠与做梦记忆(用户定稿 v1.4)

- 角色像人一样需要睡觉休息: 夜间按作息入睡,睡眠恢复体力;缺觉/熬夜触发软惩罚(次日效率/幸福下降)
- **睡觉是记忆固化的主窗口**: 入睡后对当天记忆批量整理——打分去重压缩,并由慢思考 LLM 生成 1~3 条「梦境」(当天洞察/情绪总结)写入记忆流;核心 NPC 用轻量 LLM 简化版,背景NPC 仅规则摘要零 LLM
- **记忆可查看**: 记忆面板按条目类型(事件/洞察/梦境/对话)查看,玩家 Agent 游戏内查看,NPC 记忆点击角色只读查看
- 离线期间的睡眠整理照常进行(与 §4 离线降频一致);架构落地见 arch/00 §6.4(Sleep-time Compute 模式背书)

### 2.8 素材库与后台素材管理(用户定稿 v1.5)

游戏全部美术素材(地图 tile/家具/建筑件/角色)纳入**素材库统一管理**,后台提供素材管理系统:

- **树形分类管理**: 域(domain: 户外/室内/角色/生存) → 主题(theme: 卧室/厨房/健身房…) → 类别(kind: 床/沙发/跑步机…) 的树形结构,支持分类与素材的增、删、改、查
- **可视化校验**: 素材查看支持**放大预览组成内容**(像素级放大、动画帧网格逐帧查看)——终结"盲裁无校验"的素材接入方式(v1.5 前床/冰箱/工作站三件因坐标盲裁错位返工的教训)
- **入库方式(用户定稿)**: **批量导入为主 + 手动上传为辅**——脚本批量导入素材包单件目录(如 LimeZu Theme_Sorter_Singles,自带主题分类语义,自动提取尺寸元数据),后台人工放大校验后标记启用;手动上传补充自定义素材
- **元数据体系**: 尺寸/占地(格数)/锚点/动画帧配置/等级(tier)/标签(tags),为两条演进预留:
  - 演进① 建筑与物品升级: agent 花费金币升级建筑与建筑内物品(床→高级床),tier 字段串联同 kind 不同等级素材,与成长属性契合
  - 演进② 末日生存: 生存域素材(僵尸/武器/建材/庇护所组件)经 domain 扩展入库
- **发布链路**: 素材库是管理侧唯一源头;「发布」动作将启用素材生成游戏侧产物(public/assets + manifest),渲染层消费 manifest——运行时零解析开销,库与游戏解耦
- 设计细节见 design/05-asset-library-design.md

### 2.9 随机世界生成与游戏模式(用户定稿 v1.5)

- **种子驱动整图随机(用户定稿)**: 同一随机种子生成完全一致的世界;生成范围覆盖城镇骨架(道路/功能分区/场所数量与选址)、建筑(外观/规模)、建筑内部(地板/墙体/家具选配)——全部素材从素材库按语义规则随机组合
- **引导式新世界创建**: 创建世界从单表单重构为分步向导——①游戏类型与参数 → ②agent 人数 → ③人物配置(名称/性别/人设) → ④随机种子(可自动可手填) → ⑤确认创建;已有配置项全部保留
- **游戏类型**: 成长型(现行玩法) / 生存型(末日生存,见 §2.10);生存型在玩法落地前仅作占位选项
- 生成算法与规则见 design/06-worldgen-design.md

### 2.10 末日生存玩法(远期,用户定稿 v1.5)

远期演进方向,完整设计见 design/07-survival-design.md,此处记录需求基准:

- **类沙盒生存循环**: agent 采集物资 → 合成材料 → 制造物品(工具/防御设施) → 建设与升级庇护所
- **僵尸威胁**: 僵尸随波次出现且强度递增,agent 需合作(分工采集/建造/守卫)铸就安全庇护所抵挡
- 与成长模式共用世界模拟底座与素材库(生存域素材),经济与数值体系在生存模式下有独立规则
- **时间定位(用户定稿)**: 远期立项——本期仅落地设计文档与素材库 domain 预留,实现排在成长线核心(M4~M6)验收之后

## 3. NPC 设计(用户定稿: NPC 即 Agent)

NPC 不是固定脚本,而是 Agent;按成本分三层:

| 层级 | 数量(一期) | 内核 | 成本 |
|------|-----------|------|------|
| 玩家 Agent | 1 | 完整内核: 人设卡+Memory Stream+Reflection+Planning | 慢思考 LLM(低频)+Jev(高频) |
| 核心 NPC Agent | 5~8 | 轻量 Agent: 人设卡+简化记忆,无 Reflection | 仅轻量小模型 |
| 背景NPC | 10~20 | 规则驱动,零 LLM | 零成本;被玩家/核心NPC交互时"唤醒"为轻量 Agent,交互留记忆 |

NPC 数量与人设卡统一经后台管理维护(§2.6),表中为一期默认规模。

## 4. 离线持续生活(P0 卖点)

- **常驻后端**: 游戏世界在服务端持续运行,玩家离线不暂停
- **离线降频模拟**: 玩家 Agent 离线期间继续生活,但策略性降频——日程规划 LLM 调用降为每游戏日 1 次,日程执行由规则引擎+Jev 兜底;关键社交事件才唤醒慢思考 LLM
- **飞书推送**: 离线期间关键事件(如攒够买房钱、重要社交事件)经飞书推送——P0 卖点,竞品均无
- **重进摘要**: 玩家重新上线时,给出离线期间的生活摘要
- **与暂停的关系**: 玩家主动暂停(§2.5)优先于离线模拟——暂停期间世界冻结,不发生任何离线模拟

## 5. 数值与动力系统

| 项 | 定稿 |
|----|------|
| 核心数值 | 体力值、幸福值、金币(三项一期不扩展) |
| 动力机制 | **轻抱负+软惩罚**: 角色有抱负(买房/职业目标等),抱负驱动行为;数值低不死亡,只降幸福/效率(软惩罚) |
| 时间流速 | 1 现实分钟 = 1 游戏小时,支持加速 |
| 睡眠 | 夜间按作息入睡,睡眠恢复体力;缺觉/熬夜次日效率与幸福下降(软惩罚,见 §2.7) |

## 6. 世界内容

- 小型地图,6~8 个场所(家/公司/学校/公园/商店/餐厅等);**v1.5 起城镇布局/建筑/室内由随机种子驱动生成**(§2.9),固定地图仅作为生成器的特例(内置种子)
- 核心循环: 学习(提升能力)→工作(赚金币)→生活(花金币: 消费/租房/买房/买家具);**v1.5 远期演进**: 建筑与物品金币升级(§2.8 演进①)
- 美术: **付费/开源像素素材包**(LimeZu 完整版已购,可商用需署名),不自绘;素材经素材库统一管理(§2.8)

## 7. 明确不做清单

- 多人参与游玩(一期仅单人游玩+他人只读参观,见 §2.1;多人游玩后置池)
- 移动端适配(仅桌面浏览器)
- 角色死亡/清档机制(软惩罚,永不清档)
- Agent 用量计费/商业化
- 自绘美术(仅开源素材包)
- 屏幕控制代玩路线(仅原生集成,见 research/01)
- 3D 渲染、开放大世界
