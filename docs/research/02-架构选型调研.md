# 02-架构选型调研

> 调研日期: 2026-10-03(三路并行:服务端同步/Agent内核与降本/配套组件)
> 目的: 为 arch/00 总体架构设计提供依据。已采纳结论以 ✅ 标注。

## 1. 同步方案与 tick 设计

### 1.1 对比

| 方案 | 结论 |
|------|------|
| Colyseus | 为"客户端进出房间"设计;我们是单一持久世界 7×24 与连接无关运行,模拟塞进 Room 生命周期别扭;≤10 并发其优势发挥不出来 |
| 裸 WebSocket | 最可控但要自写重连/广播分组 |
| **Socket.IO ✅** | 本机规模开销可忽略;免费获得自动重连、room 分组(玩家/参观者)、降级传输 |

- 对标: AI Town 的输入即「意图指令」(moveTo 等,RTS 式目的地+引擎寻路),客户端响应式订阅增量;generative_agents 连 WebSocket 都没有(前端步进拉快照)。慢节奏意图驱动游戏对延迟极不敏感。
- **tick ✅**: 固定 1000ms(1现实秒=1游戏分钟)+ accumulator(Fix Your Timestep);tick 管连续量(位移/数值衰减),离散事件即时触发;客户端按路径段两点插值(AI Town 用位置历史回放,我们慢一个数量级,普通 lerp 即可)
- **Phaser+React 集成 ✅**: Zustand 为唯一状态源(WS 层写入,Phaser update() 读,React selector 订阅);EventBus 仅留瞬态信号;不推荐 scene 内嵌 React DOM
- **参观者 ✅**: 同一条 WS 流+连接声明角色;首连全量快照+后续增量;只读连接指令服务端直接丢弃

## 2. Generative Agents 工程细节与降本

### 2.1 工程实现要点(可直接移植)

- **记忆检索**: 三因子各自 min-max 归一化后等权加和;recency=0.995^(距上次检索游戏小时);importance 写入时 LLM 打 1-10(刷牙≈2、约会邀约≈8);relevance=embedding 余弦。原版**无向量库**(JSON 树),我们用 pgvector 更强
- **反思触发**: 未反思记忆 importance 累计 ≥ **150**(≈最近100条普通事件);top-100 → 生成3个问题 → 洞察回写,可递归
- **规划**: 日计划(先定起床时间)→ 递归分解小时块 → 5-15分钟块;**日计划本来就是每游戏日 1 次**——离线降频需求与原版行为天然一致;每 tick 仅判定 continue/react,观察与计划矛盾才局部重规划
- 官方库结构: `reverie/backend_server/reverie.py`(主循环) + `persona/cognitive_modules/{perceive,retrieve,plan,reflect,converse,execute}`

### 2.2 成本数据

- 原版 Smallville: 25 agent×2 游戏日,论文称 "thousands of dollars",社区估 **$2000-3000/run**;后续研究(Social Norms)报告每 run >$500
- **AGA(Affordable Generative Agents, arXiv 2402.02053)**: 微调小模型"Lifestyle Policy"替代重复 LLM 环境交互 + "Social Memory"压缩对话;3 人小镇 token 降到基线 **31.1%**,多场景最高降 **96.6%**——核心 NPC 用小模型的直接先例
- **OASIS(NeurIPS 2024)**: 百万 agent 模拟,关键手段=小模型+低激活概率——背景NPC"被交互才唤醒"即此思路
- 其他: Agent Distillation(推理轨迹蒸馏进 0.5B-3B 小模型)、Light Society(按需路由 full/蒸馏模型)、prompt 缓存+批量接口为 2025 生产标配

### 2.3 双系统架构先例

- **SwiftSage(NeurIPS 2023)**: System1=7B 直觉出动作,System2=GPT-4 行动推理链;子目标完成或卡住才唤醒慢系统
- **Talker-Reasoner(DeepMind, arXiv 2410.08328)✅**: 慢 Reasoner **异步更新 belief-state 缓存**,快 Talker 读缓存不阻塞——本项目"慢思考结果如何交给快反应"的模板
- **Sleep-time Compute(Letta+UC Berkeley, arXiv 2504.13171, 2025-04)✅**: 空闲/休眠期预计算整理上下文,同等准确率测试期计算量降约 5 倍,多 agent 场景可分摊——**「睡觉做梦固化记忆」设计的研究背书**;另见「Do Language Models Need Sleep?」(2026,类睡眠固化机制)

## 3. 配套组件

- **后台面板 ✅ React Admin**: AdminJS 由 ORM 自动生成最快但绑 Prisma/Sequelize、异形表单摩擦大;Refine 无头但样板最多;React Admin 组件优先生态最成熟,自定义人设卡表单就是普通 React 组件,自带 chart+authProvider
- **数据库**: (sqlite-vec 调研结论: pre-v1 但暴力扫描毫秒级可用;**最终用户定稿 Postgres+pgvector**——多养一个常驻服务换成熟向量检索与运维生态);WAL/短事务纪律转为 Postgres 侧连接池+迁移 forward-only
- **飞书推送 ✅**: 自定义机器人 webhook(无需建应用/审核),推荐**加签**(timestamp+HMAC);限流 100次/分、5次/秒,串行队列即可;只能发群——自建个人群规避;自建应用消息仅推消息不值
- **仓库组织 ✅**: pnpm workspace(apps/* + packages/*),shared 放 Zod 协议,`workspace:*` 引用;不上 Turborepo(三包规模用不上)
- **Codiv/Jev 实测**: api.codiv.ai 在线;双轨 API——OpenAI 兼容 `/v1/chat/completions` + 原生 `/v1/systemone`(类型化答案带校准概率);`openjev-0.1`/`openjev-latest` 开放权重 Apache-2.0(基于 DiffusionGemma 26B-A4B MoE,约 4B 激活,上下文 65,536,输出类型仅 noul/choice/score);`jev-preview`/`jev-latest` 闭源托管;免费层 OpenJev 100M input tokens
- **⚠️ 关键限制 → 架构修正**: System One 是类型化决策/分类模型(70-500ms,无自由生成),**不能做 NPC 对话**;✅ 采纳分工: Jev=微决策/记忆打分/事件分类/continue-react 判定,对话生成用轻量 LLM;产品新、单厂商 → ModelRouter 适配层隔离,可随时换

## 4. 已采纳结论清单(arch/00 落地)

单体单进程(Fastify) / Socket.IO 快照+增量 / 1000ms tick+事件驱动 / Zustand 单一状态源 / 同流只读参观 / Postgres+pgvector+Drizzle / React Admin / 飞书webhook加签 / pnpm workspace / 四层决策路由(规则→Jev→轻量LLM→慢思考LLM) / Talker-Reasoner 缓存交接 / 睡眠窗口批量固化记忆
